## 1. Требования

| Что | Версия | Проверка |
|---|---|---|
| Node.js | **20 LTS или новее** | `node -v` |
| npm | 10 или новее (ставится вместе с Node.js) | `npm -v` |
| Git | любая актуальная | `git --version` |
| Свободное место | ~600 МБ (в основном `node_modules`) | — |

Отдельный сервер базы данных **не нужен**: проект использует SQLite, и база хранится в одном файле `data/domkontrol.db`.

Поддерживаются macOS, Windows 10/11 и Linux.

## 2. Установка Node.js и Git

Если `node -v` уже показывает `v20.x` или выше, этот шаг можно пропустить.

### macOS

Через [Homebrew](https://brew.sh):

```bash
brew install node git
```

Или скачайте установщик LTS-версии с [nodejs.org](https://nodejs.org). Git на macOS ставится вместе с Xcode Command Line Tools: `xcode-select --install`.

### Windows

1. Скачайте и установите **Node.js LTS** с [nodejs.org](https://nodejs.org) (галочки по умолчанию подходят).
2. Скачайте и установите **Git** с [git-scm.com](https://git-scm.com/download/win).
3. Откройте **новое** окно PowerShell или терминала и проверьте:

```powershell
node -v
npm -v
git --version
```

### Linux (Ubuntu / Debian)

Удобнее всего через [nvm](https://github.com/nvm-sh/nvm):

```bash
sudo apt update && sudo apt install -y git curl
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
source ~/.bashrc
nvm install --lts
node -v
```

## 3. Скачивание проекта

```bash
git clone https://github.com/Robert-Govard/domkontrol.git
cd domkontrol
```

Все дальнейшие команды выполняются **из папки `domkontrol`**.

> Без Git можно скачать архив: на странице репозитория **Code → Download ZIP**, затем распакуйте его и откройте папку в терминале.

## 4. Установка зависимостей

```bash
npm install
```

Команда занимает 1–3 минуты. Во время установки Prisma сама скачает движок базы данных под вашу систему.

<details>
<summary>npm 11+: сообщение про <code>install-scripts</code></summary>

В npm 11 скрипты установки пакетов по умолчанию запрещены. Нужные разрешения уже прописаны в `package.json` (секция `allowScripts`), поэтому обычно ничего делать не нужно.

Если npm всё же пишет, что скрипты `prisma`, `@prisma/engines` или `esbuild` не выполнены, разрешите их и пересоберите:

```bash
npm install-scripts approve prisma @prisma/client @prisma/engines esbuild unrs-resolver
npm rebuild
```
</details>

## 5. Настройка окружения (`.env`)

Создайте файл настроек из шаблона.

macOS / Linux:

```bash
cp .env.example .env
```

Windows (PowerShell):

```powershell
Copy-Item .env.example .env
```

Для локального демо **менять ничего не нужно**: без токена MAX проект сам включает демо-режим.

Что есть в `.env`:

| Переменная | Значение по умолчанию | Зачем |
|---|---|---|
| `DATABASE_URL` | `file:../data/domkontrol.db` | путь к файлу SQLite (относительно папки `prisma/`) |
| `DEMO_MODE` | `true` | включает эмулятор MAX на `/demo` |
| `MAX_BOT_TOKEN` | пусто | токен бота MAX; пусто — работа без MAX |
| `MAX_API_URL` | `https://platform-api2.max.ru` | адрес MAX Bot API |
| `MAX_WEBHOOK_SECRET` | пусто | секрет для проверки вебхука |
| `PUBLIC_URL` | пусто | публичный HTTPS-адрес сайта (для вебхука) |
| `ADMIN_PASSWORD` | пусто | пароль на панель УК (логин `admin`) |

> Файл `.env` содержит секреты и **не попадает в Git** (он в `.gitignore`). Не публикуйте его.

## 6. Создание базы данных

```bash
npm run db:reset
```

Команда:

1. создаёт файл `data/domkontrol.db` и все таблицы по схеме `prisma/schema.prisma`;
2. заполняет базу демо-данными: 2 дома на ул. Тестовой, 6 жителей и 26 заявок в разных статусах.

В конце должно появиться:

```
✔ Seed: 2 дома, 6 жителей, 26 заявок
```

> ⚠️ `db:reset` **полностью очищает** базу и заново заполняет её демо-данными. Удобно перед показом, но на рабочей базе с настоящими заявками так делать нельзя (см. [раздел 13](#13-обновление-проекта)).

Посмотреть содержимое базы в браузере:

```bash
npm run db:studio
```

## 7. Запуск

### Вариант А: режим разработки

Изменения в коде подхватываются автоматически.

```bash
npm run dev
```

### Вариант Б: production-сборка (рекомендуется для показа)

Работает быстрее и стабильнее.

```bash
npm run build
npm start
```

В обоих случаях откройте в браузере **http://localhost:3000**.

| Адрес | Что там |
|---|---|
| http://localhost:3000 | главная страница |
| http://localhost:3000/demo | эмулятор бота MAX (экран жителя) |
| http://localhost:3000/admin | панель управляющей компании |

Остановить сервер: `Ctrl + C` в терминале.

**Другой порт**, если 3000 занят:

```bash
# macOS / Linux
PORT=3001 npm start
```

```powershell
# Windows PowerShell
$env:PORT=3001; npm start
```

## 8. Проверка, что всё работает

Откройте `/demo` и `/admin` в двух окнах рядом и пройдите сценарий:

1. **`/demo`**: бот поздоровался и показал меню.
2. Нажмите **🏠 Сообщить о проблеме** → **💡 Электричество / освещение** → **ул. Тестовая, 10** → подъезд **2**.
3. Напишите: `Пахнет газом на 3 этаже` и нажмите отправить.
4. Нажмите **⏭ Пропустить** (или прикрепите фото скрепкой 📎), затем **✅ Отправить заявку**.
5. Бот ответит: «Заявка №… создана».
6. **`/admin`**: через пару секунд заявка появится вверху списка с меткой **Авария**.
7. Откройте её и нажмите **Принять**. Появится «Житель уведомлён».
8. **`/demo`**: придёт уведомление «Статус заявки №… изменился».

Если все 8 шагов прошли, проект установлен правильно ✅

Кнопка **↺** в шапке эмулятора очищает чат и начинает диалог заново (заявки при этом сохраняются).

## 9. Демо с телефона в той же Wi-Fi сети

`npm start` и `npm run dev` принимают подключения из локальной сети. При запуске Next.js показывает адрес:

```
- Local:        http://localhost:3000
- Network:      http://192.168.1.42:3000
```

Откройте адрес из строки **Network** на телефоне, например `http://192.168.1.42:3000/demo`. Если не открывается, разрешите Node.js входящие подключения в брандмауэре.

## 10. Подключение настоящего бота MAX

### 10.1. Создайте бота и получите токен

1. Зарегистрируйтесь на платформе MAX для партнёров: [dev.max.ru](https://dev.max.ru).
2. Создайте бота и скопируйте его **токен** в настройках.

### 10.2. Пропишите токен в `.env`

```bash
MAX_BOT_TOKEN=ваш_токен
MAX_WEBHOOK_SECRET=любая_длинная_случайная_строка
```

Случайную строку для секрета можно сгенерировать так:

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
```

После изменения `.env` перезапустите сервер.

### 10.3а. Локальная разработка: long polling

Публичный адрес не нужен. В **отдельном** окне терминала (рядом с `npm run dev`) запустите:

```bash
npm run max:polling
```

Напишите боту в MAX `/start`: ответ придёт от вашего локального сервера.

### 10.3б. Сервер: вебхук

MAX принимает вебхуки только по **HTTPS**.

1. Разверните проект на сервере с доменом и SSL ([раздел 12](#12-развёртывание-на-сервере-vps)).
   Для быстрой проверки подойдёт туннель, например `cloudflared tunnel --url http://localhost:3000`: он выдаст временный `https://…` адрес.
2. Укажите адрес в `.env`:

   ```bash
   PUBLIC_URL=https://ваш-домен.ru
   ```

3. Зарегистрируйте вебхук:

   ```bash
   npm run max:webhook
   ```

   В ответ придёт `✔ Вебхук зарегистрирован: https://ваш-домен.ru/api/max/webhook`.

> Пока вебхук активен, MAX не отдаёт события через long polling. Используйте что-то одно.

### 10.4. Проверка

```bash
curl https://ваш-домен.ru/api/max/webhook
# {"ok":true,"mode":"max"}
```

`"mode":"max"` означает, что токен подхватился. Если в ответе `"mock"`, токен не задан или сервер не перезапущен.

> Демо-страница `/demo` продолжает работать и с токеном. Если на боевом сервере она не нужна, выставьте `DEMO_MODE=false`.

## 11. Защита панели УК паролем

По умолчанию `/admin` открыта, что удобно для демо. Для реального использования задайте пароль в `.env`:

```bash
ADMIN_PASSWORD=надёжный_пароль
```

После перезапуска браузер запросит логин и пароль: логин **`admin`**, пароль — из `.env`.

## 12. Развёртывание на сервере (VPS)

Проект хранит данные в SQLite-файле, поэтому нужен сервер с постоянным диском (VPS, выделенный сервер). Serverless-хостинги вроде Vercel не подходят: файл базы там не сохраняется между запросами.

Пример для Ubuntu 22.04+:

```bash
# 1. Node.js (см. раздел 2) и pm2 для автозапуска
npm install -g pm2

# 2. Проект
git clone https://github.com/Robert-Govard/domkontrol.git
cd domkontrol
npm ci
cp .env.example .env
nano .env                # MAX_BOT_TOKEN, MAX_WEBHOOK_SECRET, PUBLIC_URL, ADMIN_PASSWORD, DEMO_MODE=false

# 3. База и сборка
npx prisma db push
npm run db:seed          # только на пустой базе, если нужны демо-данные
npm run build

# 4. Запуск в фоне с автоперезапуском
pm2 start npm --name domkontrol -- start
pm2 save
pm2 startup              # выполните команду, которую он выведет

# 5. Вебхук MAX
npm run max:webhook
```

Перед приложением поставьте Nginx или Caddy с SSL-сертификатом, который проксирует запросы на `http://localhost:3000`. Пример для Caddy (SSL выпускается автоматически):

```
ваш-домен.ru {
    reverse_proxy localhost:3000
}
```

**Резервные копии:** все данные хранятся в `data/domkontrol.db` (заявки) и `data/uploads/` (фото). Достаточно регулярно копировать папку `data/`.

## 13. Обновление проекта

```bash
git pull
npm install
npx prisma db push     # применит изменения схемы и сохранит данные
npm run build
pm2 restart domkontrol # или перезапустите npm start вручную
```

> Используйте `npx prisma db push`, а **не** `npm run db:reset`: последний удаляет все заявки.

## 14. Решение проблем

<details>
<summary><b>Порт 3000 занят</b> (<code>EADDRINUSE: address already in use :::3000</code>)</summary>

Запустите на другом порту (`PORT=3001 npm start`, см. [раздел 7](#7-запуск)) или остановите процесс, который занял порт.

macOS / Linux:

```bash
lsof -ti tcp:3000 | xargs kill
```

Windows:

```powershell
netstat -ano | findstr :3000
taskkill /PID <номер_из_последней_колонки> /F
```
</details>

<details>
<summary><b>Страница <code>/admin</code> пишет «Не удалось загрузить заявки»</b> или в логах <code>The table ... does not exist</code></summary>

База не создана или создана по старой схеме:

```bash
npm run db:reset
```
</details>

<details>
<summary><b><code>Environment variable not found: DATABASE_URL</code></b></summary>

Нет файла `.env`. Создайте его ([раздел 5](#5-настройка-окружения-env)) и выполняйте команды из корня проекта.
</details>

<details>
<summary><b><code>@prisma/client did not initialize yet</code></b> или <code>Cannot find module '.prisma/client'</code></summary>

Сгенерируйте клиент базы данных:

```bash
npx prisma generate
```

Если не помогло, проверьте раздел про `install-scripts` в [шаге 4](#4-установка-зависимостей).
</details>

<details>
<summary><b>Изменения в коде не видны после <code>npm start</code></b></summary>

`npm start` запускает последнюю сборку. После изменений выполните `npm run build` заново или работайте через `npm run dev`.
</details>

<details>
<summary><b>Эмулятор <code>/demo</code> показывает «Демо-режим выключен»</b></summary>

В `.env` стоит `DEMO_MODE=false` и задан `MAX_BOT_TOKEN`. Поставьте `DEMO_MODE=true` и перезапустите сервер.
</details>

<details>
<summary><b>Уведомление не пришло в настоящий MAX</b></summary>

- Проверьте `curl http://localhost:3000/api/max/webhook`: должно быть `"mode":"max"`.
- В панели УК после смены статуса появляется жёлтое сообщение с текстом ошибки MAX API. Чаще всего это `401` (неверный токен).
- Жители из демо-данных (Анна Петрова и другие) не настоящие пользователи MAX, им уведомления уходят только в эмулятор. Создайте заявку из настоящего MAX.
</details>

<details>
<summary><b>Бот в MAX молчит</b></summary>

- Для long polling: проверьте, что `npm run max:polling` запущен и в его окне появляются строки `← start от …`.
- Для вебхука: проверьте, что `PUBLIC_URL` открывается из интернета по HTTPS, и повторите `npm run max:webhook`.
- Если заданы и вебхук, и polling, работает только вебхук.
</details>

<details>
<summary><b>Нужно вернуть демо в исходное состояние перед показом</b></summary>

```bash
npm run db:reset
```

Затем перезапустите сервер и нажмите **↺** в эмуляторе.
</details>

## 15. Шпаргалка команд

```bash
# первый запуск
npm install
cp .env.example .env
npm run db:reset
npm run dev

# разработка
npm run dev          # сервер разработки
npm run typecheck    # проверка типов TypeScript
npm run lint         # ESLint

# production
npm run build        # сборка
npm start            # запуск сборки

# база данных
npm run db:reset     # пересоздать базу с демо-данными (удаляет всё!)
npm run db:push      # применить схему без удаления данных
npm run db:seed      # заменить данные демо-данными (тоже удаляет всё!)
npm run db:studio    # просмотр базы в браузере

# MAX
npm run max:polling  # получать сообщения MAX без HTTPS (локально)
npm run max:webhook  # зарегистрировать вебхук (нужен PUBLIC_URL)
```
